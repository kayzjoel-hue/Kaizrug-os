# Design Truth

Design Truth defines the intended architecture of Kaizrug OS.

It is not automatically runtime truth.

## Definition

```text
Design Truth = the canonical architecture, structure, and operating logic of the system.
```

It explains how the system should work.

Runtime proof explains what is actually happening.

## Three truth modes

```text
1. Runtime Reality
   What is actually happening.

2. Design Truth
   What the system is designed to be.

3. Diagnostic Truth
   What audits, scans, and reviews detect.
```

## Rule of engagement

```text
Design can propose.
Diagnostics can flag.
Only runtime ledgers and Command Center proof can certify actual reality.
```

## Design Truth controls

Design Truth governs:

- Architecture
- System roles
- Framework definitions
- Naming standards
- Public/private boundaries
- Promotion rules
- Documentation structure

## Design Truth does not govern

Design Truth does not override:

- Active execution ledgers
- Open Loops
- Runtime verification
- Financial proof
- Automation status
- Operator decisions
